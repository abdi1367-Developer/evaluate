# 🌐 سرفصل‌یاب و داور هوشمند — نسخه‌ی وب (Vercel)

همان برنامه‌ی `app.py`، اما بازنویسی‌شده با **Next.js** تا بتوانید آن را با یک کلیک روی **Vercel** دیپلوی کنید.

> **چرا Gradio روی Vercel کار نمی‌کند؟**
> Gradio به یک سرور دائمی و وب‌سوکت نیاز دارد، در حالی که Vercel فقط توابع سرورلس با محدودیت زمان (۱۰ تا ۶۰ ثانیه) و حجم (۲۵۰ مگابایت) اجرا می‌کند. پس این نسخه با Next.js نوشته شده است.

---

## ⚡ تفاوت‌های کلیدی با نسخه‌ی پایتونی

| موضوع | نسخه‌ی پایتون (Gradio) | این نسخه (Next.js / Vercel) |
| --- | --- | --- |
| محل تبدیل PDF/Word | سرور (PyMuPDF / mammoth) | **داخل مرورگر** (pdf.js / fflate) — فایل آپلود نمی‌شود |
| کلید API | فایل `.env` روی رایانه | **Environment Variable روی Vercel** (هرگز به مرورگر نمی‌رود) |
| محدودیت حجم فایل | ندارد | همان محدودیت ۴٫۵ مگابایتی آپلود ورکسل را هم ندارد، چون آپلودی انجام نمی‌شود |
| متن‌های بلند | حلقه‌ی پایتون | چند درخواست کوتاه از مرورگر (زیر سقف زمانی Vercel) |
| اجرا | `run.bat` | `dev.bat` برای محلی + `deploy.bat` یا اتصال GitHub |

## 🚀 دیپلوی روی Vercel (سه مرحله)

### روش ۱: از همین رایانه با CLI (ساده‌ترین)

1. (اختیاری) متغیرهای محیطی را روی Vercel بگذارید — کلید دیپ‌سیک را می‌توانید از داخل پنل هم ثبت کنید،
   ولی برای اینکه تغییرات پنل روی Vercel **دائمی** بماند به Vercel KV نیاز دارید:

   ```powershell
   cd web
   npx vercel login
   npx vercel link                                # ساخت/اتصال پروژه
   npx vercel env add KV_REST_API_URL production  # از Vercel KV / Upstash
   npx vercel env add KV_REST_API_TOKEN production
   npx vercel env add APP_MOBILE production        # اختیاری (پیش‌فرض 09120000000)
   npx vercel env add APP_PASSWORD production      # اختیاری (پیش‌فرض admin1234)
   npx vercel env add DEEPSEEK_API_KEY production  # اختیاری (در پنل هم می‌شود وارد کرد)
   ```

2. سپس دیپلوی کنید:

   ```powershell
   npx vercel --prod
   ```

   یا فقط `deploy.bat` را دوبار کلیک کنید (پیش از آن متغیرها را در Dashboard بگذارید).

### روش ۲: از GitHub

1. این پوشه (`web`) را در یک ریپازیتوری GitHub بگذارید.
2. در Vercel: **Add New → Project → Import** ریپازیتوری.
3. اگر پوشه‌ی `web` زیرشاخه است، در بخش **Root Directory** عبارت `web` را انتخاب کنید.
4. در **Settings → Environment Variables** این‌ها را اضافه کنید:

   | نام | مقدار | ضروری؟ |
   | --- | --- | --- |
   | `KV_REST_API_URL` | از Vercel KV / Upstash Redis | ⚠️ برای ذخیره‌ی دائمی تغییرات پنل |
   | `KV_REST_API_TOKEN` | از Vercel KV / Upstash Redis | ⚠️ برای ذخیره‌ی دائمی تغییرات پنل |
   | `APP_USERNAME` | نام کاربری اولیه (پیش‌فرض `admin`) | اختیاری |
   | `APP_MOBILE` | شماره موبایل اولیه (پیش‌فرض `09120000000`) | اختیاری |
   | `APP_PASSWORD` | رمز اولیه (پیش‌فرض `admin1234`) | اختیاری ولی توصیه‌شده |
   | `DEEPSEEK_API_KEY` | `sk-...` | اختیاری (در پنل هم می‌شود وارد کرد) |
   | `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | اختیاری |
   | `DEEPSEEK_MODEL` | `deepseek-chat` یا `deepseek-reasoner` | اختیاری |

5. **Deploy** را بزنید. تمام! Framework به‌صورت خودکار Next.js تشخیص داده می‌شود و به هیچ تنظیم دیگری نیاز نیست.

> 🔐 **مهم:** برنامه صفحه‌ی ورود دارد. بعد از اولین ورود با حساب پیش‌فرض، حتماً از «پنل ← حساب کاربری» نام کاربری، شماره موبایل و رمز عبور را عوض کنید.

## 💻 اجرای محلی

روی `dev.bat` دوبار کلیک کنید، یا در ترمینال:

```powershell
cd web
npm install
npm run dev
```

سپس مرورگر را روی <http://127.0.0.1:3000> باز کنید.

برای اجرای محلی باید فایل `.env.local` وجود داشته باشد (از `.env.local.example` کپی بگیرید):

```ini
APP_USERNAME=admin
APP_MOBILE=09120000000
APP_PASSWORD=admin1234

# اختیاری: اگر خالی بماند، کلید را از داخل پنل هم می‌توانید وارد کنید
DEEPSEEK_API_KEY=sk-...
```

**ورود پیش‌فرض بعد از اولین اجرا:** شماره موبایل `09120000000` (یا نام کاربری `admin`) با رمز `admin1234`.
در اجرای محلی، تغییرات پنل در فایل `web/.data/state.json` ذخیره می‌شوند (این پوشه در `.gitignore` است).

> `npm install` به‌طور خودکار فایل `public/pdf.worker.min.mjs` را می‌سازد تا خواندن PDF به اینترنت/CDN وابسته نباشد.

**پیش‌نیاز:** Node.js نسخه‌ی ۲۰ یا بالاتر.

## 🔐 ورود، پنل و ذخیره‌سازی

**ورود:** با **شماره موبایل** یا **نام کاربری** + رمز عبور. رمزها با `scrypt` هش می‌شوند و نشست در یک
کوکی `HttpOnly` امضاشده با `HMAC-SHA256` نگه داشته می‌شود (یک هفته). همه‌ی مسیرهای API فقط با نشست
معتبر پاسخ می‌دهند و پس از چند تلاش ناموفق، ورود موقتاً قفل می‌شود.

**پنل (`/panel`) چه کارهایی می‌کند؟**

| بخش | توضیح |
| --- | --- |
| 💾 وضعیت ذخیره‌سازی | نشان می‌دهد تنظیمات کجا ذخیره می‌شوند (KV / فایل محلی / حافظه‌ی موقت). |
| 👤 حساب کاربری | تغییر **نام کاربری**، **شماره موبایل** و **رمز عبور** (با تأیید رمز فعلی). |
| 🔑 تنظیمات دیپ‌سیک | ثبت **کلید API**، آدرس سرویس و مدل + دکمه‌ی **«تست اتصال و فعال‌سازی»** (در این مرحله فقط دیپ‌سیک). |
| 🔀 تبدیل‌کننده‌ها | روش پیش‌فرض تبدیل + کلیدهای اختیاری Jina / Datalab Marker / Mistral OCR. |
| 🧩 سرفصل‌های پیش‌فرض | ویرایش جعبه‌های «بخش‌های مورد انتظار» برای مقاله، کتاب و گزارش. |

**کلید دیپ‌سیک کجا نگه داشته می‌شود؟** فقط روی سرور. به مرورگر تنها نسخه‌ی ماسک‌شده (مثل `sk-abc••••••1234`)
فرستاده می‌شود. اگر متغیر محیطی `DEEPSEEK_API_KEY` تنظیم شده باشد، همیشه به‌عنوان پشتیبان فعال است و لازم
نیست در پنل هم وارد شود. کلید ثبت‌شده در پنل فقط بعد از موفقیت «تست اتصال» فعال می‌شود.

**ذخیره‌سازی دائمی روی Vercel:** برای اینکه تغییرات پنل (کلید، رمز عبور، سرفصل‌ها) بعد از ری‌استارت یا
دیپلوی جدید باقی بماند، یک دیتابیس Redis (Vercel KV یا Upstash) به پروژه وصل کنید؛ در آن حالت
متغیرهای `KV_REST_API_URL` و `KV_REST_API_TOKEN` خودکار تنظیم می‌شوند. بدون آن، تغییرات فقط در حافظه‌ی
همان نمونه می‌ماند و پنل هم هشدار می‌دهد.

**تبدیل آنلاین (مرحله‌ی «اول سرویس‌های رایگان»):**

| سرویس | کلید لازم؟ | مناسب برای |
| --- | --- | --- |
| Jina Reader | ❌ رایگان | لینک صفحه‌ی وب یا PDF آنلاین (`https://r.jina.ai/<url>`) |
| Datalab Marker | ✅ کلید در پنل | فایل آپلودی (تبدیل دقیق‌تر PDF) |
| Mistral OCR | ✅ کلید در پنل | PDF اسکن‌شده/تصویری |

اگر هیچ‌کدام ممکن نباشد، تبدیل محلی در مرورگر انجام می‌شود و فایل به هیچ سروری نمی‌رود.

## 🧠 چطور توکن کم مصرف می‌شود؟

1. **تبدیل به Markdown:** متن خام PDF/Word پر از اطلاعات قالب‌بندی (فونت، موقعیت، جدول‌های تزئینی) است؛ Markdown فقط ساختار مفید را نگه می‌دارد. شکست خط‌های PDF هم ادغام می‌شوند و شماره‌ی صفحه‌ها حذف می‌شوند.
2. **متن کوتاه (پیش‌فرض تا ۶۰٬۰۰۰ کاراکتر):** یک‌جا برای داوری فرستاده می‌شود.
3. **متن بلند (کتاب):** بر اساس مرز سرفصل‌ها به بخش‌ها تقسیم می‌شود، هر بخش جداگانه خلاصه می‌شود و در پایان
   «سرفصل‌ها + خلاصه‌ها» برای داوری نهایی ارسال می‌شود. یعنی به‌جای صدها هزار توکن، چندین هزار توکن.
4. **سقف کاراکتر** را می‌توانید در بخش ۳ بین ۳۰٬۰۰۰ / ۶۰٬۰۰۰ / ۱۰۰٬۰۰۰ تغییر دهید.

## ⚠️ محدودیت‌ها (صادقانه)

- **PDF اسکن‌شده:** بدون OCR متنی استخراج نمی‌شود.
- **PDF چندستونه:** ترتیب خواندن ممکن است درست نباشد (pdf.js سطرها را بر اساس ترتیب جریان متن می‌دهد).
- **نمره‌ی مدل:** نمره‌ی نهایی نظر هوش مصنوعی است، نه داوری رسمی. برای دقت بیشتر مدل `deepseek-reasoner` را انتخاب کنید.
- **سقف ۶۰ ثانیه‌ای توابع Vercel:** هر درخواست جداست، پس مشکلی پیش نمی‌آید؛ اما برای متن‌های خیلی بزرگ تعداد درخواست‌ها زیاد می‌شود (که در بخش ۳ قبل از شروع نمایش داده می‌شود).
- **۱۰ بخش حداکثری:** اگر متن از این بیشتر شود، بخش‌های انتهایی در یک بخش ادغام می‌شوند تا هزینه کنترل شود.
